# Windows 硬件监控网页 - 开发文档与还原指南

备份日期：2026-10-30
当前版本：稳定运行版

---

## 一、项目概述

一个部署在 Windows 主机上的硬件信息监控网页，通过手机浏览器公网访问，实时查看 CPU、GPU、主板、内存、硬盘的温度、负载、频率、功耗、风扇转速等数据。

### 核心特性

- 刷新间隔：0.5 秒（2 Hz）
- 两个页面：纯数据页 + 专业图表页
- 图表库：ECharts 5.5（本地部署，不依赖外部 CDN）
- 公网访问：通过 Docker Nginx 反向代理
- 开机自启：Windows 计划任务，最高权限运行，无需手动点 UAC
- 数据保留：图表保留最近 30 个数据点（约 15 秒）

## 二、系统架构

```
公网手机浏览器
       |
       v
路由器端口映射 10095 TCP
       |
       v
Docker Nginx 容器 (monitor-proxy)
  端口 10095:80
  作用：反向代理 + 公网入口
       |
       |  Host 头改为 localhost:19092
       v
Windows PowerShell 监控服务 (admin-monitor.ps1)
  端口 19092（localhost only）
  权限：管理员（最高权限）
       |
       v
LibreHardwareMonitorLib.dll
  作用：读取 Windows 硬件传感器
       |
       v
CPU / GPU / 主板 / 内存 / 硬盘 / 网卡
```

### 为什么是这个架构

1. **LibreHardwareMonitor**：Windows 原生开源硬件监控库，能直接读取 CPU MSR、主板 Super I/O、GPU 传感器，是 Windows 下读取硬件数据最靠谱的方案。
2. **PowerShell + HttpListener**：轻量，不需要额外安装运行时，直接加载 DLL 就能提供 Web API。
3. **Docker Nginx 反向代理**：
   - 对外提供标准 80 端口，容器内转发到主机
   - 方便统一管理多个 Web 服务（Obsidian、WebDAV 等都用同样的模式）
   - 解决 HttpListener 只能监听 localhost 的问题，通过设置 Host 头转发
4. **计划任务而不是 Windows 服务**：
   - 配置简单，不需要注册服务
   - 可以设置最高权限（RunLevel Highest）
   - 登录时自动启动，用户会话内运行，兼容性好

## 五、关键传感器名称

前端代码通过这些名称查找传感器，LibreHardwareMonitor 升级后如果名称变了，需要同步修改。

### CPU（类型：Cpu，共 47 个传感器）

| 指标 | 传感器名称 | 类型 | 典型值 |
|---|---|---|---|
| CPU 总负载 | CPU Total | Load | 10-30%（空闲） |
| CPU 核心最大负载 | CPU Core Max | Load | 20-50% |
| CPU 封装温度 | CPU Package | Temperature | 45-60°C |
| CPU 封装功耗 | CPU Package | Power | 25-50 W |
| CPU 核心频率 | CPU Core #1 | Clock | 约 4000 MHz |

### GPU（类型：GpuAmd，共 40 个传感器）

注意：类型是 **GpuAmd**，不是 Gpu。

| 指标 | 传感器名称 | 类型 | 典型值 |
|---|---|---|---|
| GPU 核心负载 | GPU Core | Load | 0%（空闲） |
| GPU 显存负载 | GPU Memory | Load | 0%（空闲） |
| GPU 核心温度 | GPU Core | Temperature | 50-60°C |
| GPU 显存温度 | GPU Memory | Temperature | 60-70°C |
| GPU 热点温度 | GPU Hot Spot | Temperature | 55-65°C |
| GPU 核心频率 | GPU Core | Clock | 空闲时约 30 MHz，满载约 1800 MHz |
| GPU 显存频率 | GPU Memory | Clock | 约 1792 MHz |
| GPU 风扇 | GPU Fan | Fan / Control | 0（空闲停转）或更高 |

### 主板（类型：Motherboard，共 37 个传感器）

- 风扇：Nuvoton NCT6687D - CPU Fan、Pump Fan、System Fan #1-4
- 电压、温度等：完整列表见数据页

## 六、计划任务配置

任务名称：**HardwareMonitor**

### 配置详情

- **运行级别**：最高（RunLevel Highest），管理员权限
- **触发器**：当前用户登录时（AtLogOn）
- **操作**：`powershell.exe -ExecutionPolicy Bypass -WindowStyle Hidden -File E:\doubao_workspace\admin-monitor.ps1`
- **设置**：
  - 允许电池供电时运行
  - 电池供电时不停止
  - 错过启动时间后自动启动
  - 失败重启：3 次，间隔 1 分钟
  - 无执行时间限制（一直运行）

### 管理命令

```powershell
# 查看状态
Get-ScheduledTask -TaskName HardwareMonitor
Get-ScheduledTaskInfo -TaskName HardwareMonitor

# 手动启动
Start-ScheduledTask -TaskName HardwareMonitor

# 手动停止
Stop-ScheduledTask -TaskName HardwareMonitor

# 删除任务
Unregister-ScheduledTask -TaskName HardwareMonitor -Confirm:$false
```

## 八、常见问题排查

### 1. CPU 温度、功耗显示 0

**原因**：监控服务没有管理员权限。

**解决**：
- 确认计划任务正在运行，而不是手动启动的普通 PowerShell
- 检查任务的 RunLevel 是否为 Highest
- 重启任务：`Start-ScheduledTask -TaskName HardwareMonitor`

### 2. 页面显示旧版本，修改不生效

**原因**：旧的监控进程（working-monitor.ps1 等）还在运行，占用了端口。

**排查步骤**：
1. 列出所有 PowerShell 进程的命令行：
   ```powershell
   Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" | Select-Object ProcessId, CommandLine
   ```
2. 杀掉所有包含 `monitor.ps1` 的旧进程
3. 确认端口监听：`netstat -ano | findstr :19092`
4. 浏览器加版本参数绕过缓存：`charts.html?v=10`

### 3. Nginx 配置加载失败，报错 unknown directive

**原因**：配置文件开头有 UTF-8 BOM 标记，nginx 不识别。

**解决**：用无 BOM 的 UTF-8 重新保存：
```powershell
$content = Get-Content monitor-nginx.conf -Raw
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText("monitor-nginx.conf", $content, $utf8NoBom)
```

然后平滑重载：`docker exec monitor-proxy nginx -s reload`

### 4. Docker 容器访问主机服务返回 400 Bad Request

**原因**：HttpListener 只监听 localhost，容器通过 host.docker.internal 访问时 Host 头不匹配。

**解决**：Nginx 配置里加 `proxy_set_header Host "localhost:19092";`（已配置）

### 5. GPU 数据找不到

**原因**：AMD 显卡的类型是 `GpuAmd`，不是 `Gpu`。

**解决**：前端代码里判断 `data[i].type === 'GpuAmd'`（已配置）

### 6. 负载频率图里负载线贴在 0 轴看不清

**原因**：两条线共用一个 Y 轴，频率 4000 MHz 把纵轴撑大，10-30% 的负载看起来接近 0。

**解决**：使用双 Y 轴（yAxisIndex 0 和 1），左边负载 0-100%，右边频率 MHz（已配置）

## 九、完整还原步骤（搞坏了照着做）

### 前提条件

- Docker Desktop 已安装并运行
- 路由器端口映射 10095 已配置
- 本备份文件夹完整可用

### 步骤 1：恢复文件

把备份里的文件复制到 `E:\doubao_workspace\`：

```powershell
$backup = "E:\doubao_workspace\backups\hardware-monitor-20261030"
$target = "E:\doubao_workspace"

# 复制核心文件
Copy-Item "$backup\admin-monitor.ps1" $target -Force
Copy-Item "$backup\charts.html" $target -Force
Copy-Item "$backup\data.html" $target -Force
Copy-Item "$backup\echarts.min.js" $target -Force
Copy-Item "$backup\monitor-nginx.conf" $target -Force
Copy-Item "$backup\install-task.ps1" $target -Force

# 复制 LibreHardwareMonitor
Copy-Item "$backup\LibreHardwareMonitor" $target -Recurse -Force
```

### 步骤 2：确认 Nginx 容器存在

如果容器还在，只需要确认配置挂载正确：

```powershell
# 查看容器
docker ps | findstr monitor-proxy

# 测试配置
docker exec monitor-proxy nginx -t

# 平滑重载
docker exec monitor-proxy nginx -s reload
```

如果容器被删了，重新创建：

```powershell
docker run -d `
  --name monitor-proxy `
  --restart always `
  -p 10095:80 `
  -v "E:\doubao_workspace\monitor-nginx.conf":/etc/nginx/conf.d/default.conf:ro `
  nginx:alpine
```

### 步骤 3：安装计划任务（需要管理员权限，只做一次）

右键以管理员身份运行 PowerShell，执行：

```powershell
& "E:\doubao_workspace\install-task.ps1"
```

或者手动右键 `install-task.ps1`，选择"使用 PowerShell 运行"，在 UAC 弹窗点"是"。

### 步骤 4：验证

1. 本地测试：
   ```powershell
   curl.exe http://localhost:19092/api/data
   ```

2. 公网测试：
   - 图表页：http://caiverson.asuscomm.com:10095/charts.html
   - 数据页：http://caiverson.asuscomm.com:10095/data.html

3. 确认计划任务状态：
   ```powershell
   Get-ScheduledTask -TaskName HardwareMonitor
   ```

### 步骤 5：重启电脑验证自启

重启一次电脑，登录后等 1 分钟，直接访问公网页面，确认服务自动启动了。

## 十、技术选型踩过的坑（避免再走弯路）

### 已验证的死路

1. **Netdata Docker**：只能监控 WSL/容器环境，读不到 Windows 主机的硬件传感器（CPU 温度、GPU 温度、风扇转速等），完全不适用。
2. **普通权限运行 LibreHardwareMonitor**：CPU 温度、功耗、主板传感器全部读不到，必须管理员权限。
3. **端口 10093**：被 Windows Hyper-V 动态端口范围占用，无法监听。
4. **单 Y 轴显示负载 + 频率**：频率数值太大，负载线被压缩到几乎看不见，必须双 Y 轴。
5. **Glances / 纯数字列表**：用户明确拒绝，要求专业图形化界面。
6. **坚果云免费版 WebDAV**：API 请求限制，大量文件同步失败（和本项目无关，记录备用）。

### 为什么选 ECharts

- 成熟专业，功能完整，支持仪表盘、折线图、双 Y 轴、tooltip
- 可以完全本地部署，不依赖外部 CDN
- 文档齐全，中文资料多
- 体积可控（min 版约 1 MB）

## 十一、维护建议

1. **每次修改前先备份**：在 `backups/` 下创建带日期的新文件夹，不要只依赖一个备份。
2. **不要随便升级 LibreHardwareMonitor**：升级后传感器名称可能变化，需要同步验证前端代码。
3. **调试时先在本地测试**：确认 `localhost:19092` 正常后再看公网，避免多层问题混在一起。
4. **一次只改一个变量**：改完就验证，不要同时改多个地方，出问题不好定位。
5. **浏览器缓存**：前端页面更新后，URL 后面加 `?v=数字` 绕过缓存，或者用无痕模式测试。
